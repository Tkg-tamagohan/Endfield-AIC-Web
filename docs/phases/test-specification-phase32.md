## 1. モデル検査（xUnit）

### 処理ランの投入と反映（DSP）: DisposalTests.cs（新規）

フィクスチャは `CalculationFixtures` に処理レシピ（`Outputs` 0 件）と廃水系アイテムを持つ構成を追加して組み立てる。ゴールデン値はフィクスチャ定義から検算して記述し、実装から逆引きしない。

| ID | 内容 | 条件 | 期待 |
|---|---|---|---|
| DSP-01 | 余剰の処理ランが登録され収束する | 副産物として廃水系アイテムが余剰になる計画に、処理レシピ（`Outputs` 0 件）を登録 | 処理レシピの `RecipeRun` が余剰全量分のサイクルで追加され、対象アイテムの需要に処理量が計上され、余剰一覧から消える。処理ランの付け外しが反復間で振動せず、2 反復以上の評価でも収束限界に達しない |
| DSP-02 | 再利用充当後の残りだけ処理される | 廃水系アイテムを再利用するレシピが需要にある構成 | 再利用分は通常の需要として充当され、残った余剰のみが処理対象になる |
| DSP-03 | 計算目標のアイテムは処理対象外 | 計算目標に指定したアイテムが余剰を持つ構成 | 目標アイテムの余剰は処理されず余剰一覧に残る |
| DSP-04 | 処理対象でない余剰はそのまま残る | 処理レシピの入力に登場しないアイテムの余剰がある | その余余剰は従来どおり余剰一覧に残る |
| DSP-05 | 適格な処理レシピ・ペアがない場合 | 処理レシピ未登録、または非有効イベントの処理レシピ・環境ペアのみ | 需要は加えられず余剰のまま残り、追加の警告は出ない |
| DSP-06 | 処理ランの設備台数・消費電力が計上される | DSP-01 の構成 | `FacilityRequirements` に処理設備の実数・切上げ台数が現れ、`TotalPowerConsumption` に含まれる |
| DSP-07 | 処理ランの固定消費が追加需要になる | 固定消費を持つペアの処理レシピ | 固定消費の需要が `個/分 × 切上台数` で計上される |
| DSP-08 | 環境を要するペアの処理ラン | `EnvironmentId` を持つペアの処理レシピ | 処理ランの機械数が環境の利用機械数に計上され、散布機台数・ガス消費に反映される |
| DSP-09 | 複数入力の処理レシピ | 対象アイテムと別アイテムを入力に持つ処理レシピ | サイクル数は対象アイテムの余剰で決まり、他入力はそのサイクルに従う消費として需要に計上される。他入力に余剰が足りない分は通常の需要として残る |
| DSP-10 | 処理が誘発する余剰も収束反復で処理される | 処理ランの固定消費等が副産物を持つ生産を誘発する構成 | 新たに生じた余剰が以降の反復で処理対象になり、収束する |
| DSP-11 | 処理レシピの既定選択 | 同一対象に複数の処理レシピが候補になる構成 | `VersionAdded` 最新 → 実効処理レート（1 サイクル入力量 ÷ 最小 `CycleTime` ×60）最大 → `Id` 昇順で選ばれる |
| DSP-12 | 処理ペアの既定選択 | 同一処理レシピに複数ペア行がある構成 | `CycleTime` 最小が既定になり、同率は BT の順（`FixedConsumption` なし → `RatePerMinute` 小 → `EnvironmentId=null` → `FacilityId` 昇順） |
| DSP-13 | 引き戻しで処理ランが除去されない | 副産物充当の変動がある計画で処理ランが稼働中 | 処理ランは `Selection` に現れなくても `Retract` で除去されず、登録した需要分の稼働が残る |
| DSP-14 | 処理のために対象アイテムを新規生産しない | 生産が縮小して余剰が減る構成 | 処理需要は現在余剰へ追随して減額され、処理対象アイテムの生産は増えない |
| DSP-15 | 未調整ビューの処理表示 | DSP-01 の構成を未調整ビューで見る | 処理ランはラン倍率でスケールし、処理消費も倍率でスケールして未調整の利用可能量内にクランプする。未調整の余剰は処理後の残量を表示する（UnadjustedViewTests 側で検査） |
| DSP-16 | 処理ランに推奨流量制限が出ない | 処理ランが端数機械を持つ構成 | `FlowAdjustments` に処理レシピの入力制限が出ない |
| DSP-17 | カバー不足で処理ランが削られる | 環境を要するペアの処理レシピで、散布機台数上書きが利用機械数を下回る | 削られた分は処理需要を減額して整合され、処理しきれない分は余剰に残る（未充足にはならない） |
| DSP-18 | 出力なしレシピは需要展開の選択に現れない | 処理レシピの入力アイテムに通常の需要がある構成 | そのアイテムの生産選択に出力なしレシピは選ばれず、処理需要の計上のみで消費される |
| DSP-19 | 複数の対象アイテムが同一処理レシピを選ぶ | 2 つの廃水系アイテムに余剰があり、両者を入力に持つ処理レシピが 1 件 | 別ランを増やさず 1 つのランにまとめ、サイクル数は廃水系入力すべての「残り余剰 ÷ 1 サイクル入力量」の最小値を上限とする。先に評価したアイテムの余剰を超える消費は生じない（例: A 余剰 10・B 余剰 20・1 サイクル 1A+1B なら合計 10 サイクル、B の残り 10 は余剰に残る） |
| DSP-20 | 処理ランが選択ペアを保持する | 同一設備に `CycleTime` の異なる 2 ペアを持つ処理レシピ | ユニット割当・未調整ビュー・グラフのペア解決が選択したペアを使い、先頭ペアの CycleTime・環境へずれない |
| DSP-21 | 未調整で処理消費が利用可能量を超えない | 未調整のラン倍率で処理量が未調整の余剰を超える構成 | 処理消費は利用可能量内にクランプされ、負の余剰や過剰な処理表示にならない |

## 5. 手動確認項目（ブラウザプレビュー）

Admin で処理レシピを登録し、公開アプリ・管理ツールの計算ページで確認する。実装のブラウザプレビューをユーザーに操作してもらい、確認後に実施する。
実マスタに処理レシピは未登録のため、検証用のマスタは Admin の編集経路で用意するか、テスト用フィクスチャ注入（fixture-injection-blazor-testing スキル）で行う。

| ID | 確認内容 |
|---|---|
| MN-130 | 管理ツールで出力 0 件の処理レシピを登録・保存でき、検証エラーが出ない |
| MN-131 | 汚水など余剰のある廃水系アイテムの計画で、設備一覧に処理設備の台数・消費電力が現れ、余剰一覧からそのアイテムが消える |
| MN-132 | 素材行で処理対象アイテムの処理消費が識別できる表示になる |
| MN-133 | グラフで処理対象アイテムのノードが紫・メタ行に処理情報が出て、処理設備のノードがない。台数分表示でも同じ |
| MN-134 | 処理設備が生産ラン・散布機を兼ねる構成では設備ノードが残り、処理情報はアイテム側にのみ出る |
