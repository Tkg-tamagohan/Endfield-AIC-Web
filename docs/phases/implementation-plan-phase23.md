## 1. スコープ

### やること

生産フローグラフ（Phase 15）の層割りを改訂し、目標アイテムがグラフ中間に来てしまう問題を解消する。

- 層割りの起点を「供給源（入力のないノード）」から「消費されないアイテム（Layer0）」へ改め、各ノードの層を Layer0 から上流へ遡る最長距離とする（仕様決定 BF）。表示は Layer0 を右端列とし、物の流れの向きは従来どおり左→右とする
- Layer0 の起点は、目標アイテムと、下流エッジを持たないアイテム（未消費の副産物・余剰・未充足の需要）とする。消費される目標は規則どおり大きい層へまとめ、消費設備の直上流に置く（仕様決定 BG）
- 循環を閉じる後退エッジは層割りに使わず、ループ構成ノードは自然な深さの層に置く。ループ内の目標は Layer0 に留まる（仕様決定 BH）

### やらないこと

- 層内の順序付け（バリセンター法）は変更しない
- エッジ流量・容量超過判定・台数分表示のロジックは変更しない（表示位置の決め方のみの改訂）
- 描画側（`flow-graph.js`・`FlowGraph.razor`）の変更。ランク→x 変換は反転値を渡すだけで従来どおり
- リスト表示側の変更。管理ツールへの展開

## 3. モデルの変更詳細

### 層割り（BF〜BH）

Layer0 は、目標アイテム（`IsTarget`）と、どの設備にも消費されない（下流エッジを持たない）アイテムとする。後者には未消費の副産物・余剰・生産経路のない需要が含まれる。
各ノードの層は `layer(n) = 1 + max(確定済みの下流ノードの層)` で、下流へ向かうエッジをたどって最長距離を取る。同一アイテムが複数の経路で異なる深さを持つときは最長距離（大きい層）にまとまる。
下流が未確定のエッジ（循環を閉じる後退エッジ）は層の計算に使わない。
採取ノードは最深の供給先の次層に自然に沈み、設備ユニットノードは出力アイテムを共有するため設備と同じ規則で層が決まる。
消費される目標アイテムは Layer0 に置かず、消費設備の直上流の層に置く（BG）。
循環の残存ノードは、目標アイテムを種に確定済みの下流側だけで層を決める。ループ内の目標は Layer0 に留まり、循環は後退エッジとして描画される（BH）。起点に届かない閉じた循環は同じ規則で打ち切る。
複数の出口を持つ循環では、仮確定したノードに後からより深い層が届くことがある。自分自身を経由しない下流からの更新だけを取り込む緩和を行い、最長距離が確定するまで層を引き上げる（循環内のエッジが逆向きに描かれないようにするため）。
散布機など出力を持たない設備ノード（終端ノード）は層割りの対象外とし、そのエッジは下流距離に数えない。終端ノードは最も深い消費アイテムの直下流に置く。
表示は最大層からの反転（`rank = maxLayer − layer`）で、Layer0 が右端列になる。

## 4. 確定した UI 上の判断

実装中に変更する場合は本節を更新する。

1. Layer0 は右端列とし、物の流れの向き（左→右）は従来どおり維持する（BF で採用）
2. 消費される目標は Layer0 に置かず消費設備の直上流に置く（BG で採用。Layer0 への仮想ノード追加はしない）

## 6. 受け入れ条件

- 目標アイテムが常に右端列（Layer0）に現れ、素材チェーンが左へ積み上がる
- 消費される目標は消費設備の直上流の層に置かれる
- 未消費の副産物・余剰も右端列にまとまる
- ループ内の目標は右端に留まり、循環は後退エッジとして描かれる
- `dotnet build` と `dotnet test` が全緑である
