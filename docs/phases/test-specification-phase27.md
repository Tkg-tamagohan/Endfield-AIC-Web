## 1. モデル検査（xUnit）

### 利用機械数の出力（ENV）: EnvironmentTests

| ID | 内容 |
|---|---|
| ENV-17 | `EnvironmentRequirement.UsedMachineCount` はその環境を要するランの機械数合計（実績＋有効削減機械数）を返す。i-hp 65/分（4.33 機）で約 4.33。`RequiredDispenserCount` の分子と同じ量であることを確認する |

### 入力範囲の検証（ECN・ERC）: CalculationInputBuilderTests

| ID | 内容 |
|---|---|
| ECN-01 | 改訂。範囲内の台数（min=2・max=5 で 3）は `EnvironmentCountOverride` になり、空欄行は自動値扱いで無視される |
| ECN-02 | 改訂。上限ちょうど（min=2・max=5 で 5）は受理する |
| ECN-03 | 改訂。非整数・負・上限超過（6）はエラー（メッセージに環境名と `2〜5` の範囲を含む） |
| ECN-04 | 下限ちょうど（min=2・max=5 で 2）は受理する |
| ECN-05 | 下限未満（min=2・max=5 で 0・1）はエラー。0 台も範囲外として同じメッセージで拒否する（BS） |
| ERC-01 | 改訂。min〜max の整数文字列はそのまま保持する（下限ちょうど・上限ちょうどを含む） |
| ERC-02 | 改訂。新しい上限を超えた保持値は空欄へ戻す（クランプしない） |
| ERC-03 | 据置。非整数・負数・空欄・空白のみは空欄（自動値）のまま/へ戻す |
| ERC-04 | 下限未満の保持値（min=2 で "1"・"0"）は空欄へ戻す（AH の範囲読み替え） |

### 範囲の算出（PVD）: PlanViewDefaultsTests

| ID | 内容 |
|---|---|
| PVD-03〜05 | 改訂。`DispenserLimit` を `DispenserRange` へ置き換えるため、各ケースの期待を (Min, Max) へ読み替える（Min=必要台数、Max=ceil(利用機械数)。登場しない環境は (0, 0)） |
| PVD-06 | 改訂。カバー不足で稼働が止まった環境でも (必要台数, ceil(利用機械数)) が返る（実績＋有効削減機械数を分母とする） |
| PVD-07 | `DispenserRange` は利用機械数の実数値を切上げて上限とする。利用機械数 4.33・必要台数 2 で (2, 5) |

### Domain の防御的経路（環境群の維持）

| ID | 内容 |
|---|---|
| ENV-10〜16 | 据置。UI から到達不能になるカバー不足系（クランプ・警告・比例配分）は、Domain へ直接 `EnvironmentCountOverride` を渡す経路で維持する（計画書 §4-4） |
| VWU-07〜09 | 据置。未調整ビューのカバー上限反映も同じ防御的経路で維持する |

## 2. 手動確認項目

E2E 検証は WebGPU 対応 Chrome で行う。範囲表示・入力エラー・ガス消費は実マスタ（息壌の安定環境）で検証し、管理ツールの計算プレビューは `admin-driven-fixture-blazor-testing` の手順に従う。

| ID | 対象 | 条件 | 期待 |
|---|---|---|---|
| MN-116 | 範囲表示 | 同梱マスタで息壌 150/分（機械数 5.0・必要台数 2） | 環境行が「（自動 2 台・2〜5 台）」系の範囲表示になる |
| MN-117 | 上限超過側の受理 | 散布機を 3〜5 にする | 散布機台数・ガス消費・消費電力が台数比例で増え、生産・未充足は変わらない（警告も出ない） |
| MN-118 | 下限未満の拒否 | 散布機を 0 または 1 にする | 入力エラーが表示され、計算は更新されない（未充足にはならない） |
| MN-119 | 保持値の整合 | 台数 4 で計算後、目標を下げて上限が 4 未満になる | 入力が自動値へ戻り、整合後の入力で再計算される |
| MN-120 | Admin 側の同一動作 | 管理ツール計算プレビューで同等の計画 | 範囲表示・入力エラー・台数超過時の消費が公開 App と同じ動作になる |
| MN-121 | ヒント文 | 環境節 | ヒントが新しい入力範囲と、必要台数を超える台数がガス消費・消費電力へ比例する旨を説明している |
