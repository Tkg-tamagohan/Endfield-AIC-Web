## 1. 自動テスト（xUnit）

新規ケースなし。変更対象は `flow-graph.js` のエッジ幾何のみであり、Domain・Application の入出力契約は不変である。既存テスト全緑（`dotnet test`）を回帰として確認する。

## 2. 手動確認項目（ブラウザプレビュー）

WebGPU 対応 Chrome で公開アプリの計算ページを開く。主な検証計画は `recipe-heavyXiragen01`（重息壌ガス）を含む目標で、種↔作物循環の後退エッジと共有設備（精錬炉）から深い層への後退エッジを同時に含む。

| ID | 確認内容 | 手順 | 期待 |
|---|---|---|---|
| MN-158 | 巨大ループの非発生 | 重息壌ガスを目標に含む計画を縦表示で出す | 全ての後退エッジの弧がノード群の外縁＋余白の範囲に収まり、画面外へ大きくはみ出す弧がない。初期表示でノードとループがまとめて収まる |
| MN-159 | ソースが行端にあるループの側 | 同上（`芽針 → 採種機`：左端 rank4 → 右端 rank1 の後退エッジ） | ループが左側へ小さく膨らむ（実到達は左外縁＋余白程度）。途中のノードカードを背面通過してよい |
| MN-160 | 側選択の一貫性 | 同上の計画で複数の後退エッジを見る | 各後退エッジが必要張り出し量の小さい側へ膨らむ。左右が同量のエッジはソースノードが行外縁に近い側になる |
| MN-161 | 全行スパンの後退エッジ | 同上（`精錬炉 → 炭塊・赤銅塊` など、浅い設備から最深層への辺） | ノード群の外周を回る弧として描かれ、張り出しが従来（最大 2,400px 超）より小さく収まる |
| MN-162 | 交差の背面通過 | MN-158 の計画でループがノードカードと重なる部分を見る | 交差部分はカードの背面に隠れて見え、カードの上を線が通過する見え方にはならない |
| MN-163 | 単純循環の回帰 | 種↔作物循環のみの小さい計画（MN-85/98 相当）を縦表示で出す | 従来どおり側面へ膨らむループとして描かれる。背面通過が生じても弧がノード群外縁＋余白内に収まる |
| MN-164 | 横表示の非影響 | 同計画を横表示へ切替する | 横表示の後退エッジ・前進エッジの描画が従来どおりである |
| MN-165 | フィット境界の回帰 | 同計画でフィットボタン・拡大縮小を試す | フィットで全内容が収まる。世界矩形が極端に肥大せず、等倍前後で全ノードが読める |

## 3. 受け入れ条件との対応

- MN-158・161 が張り出し量の有界化（発散の解消）を、MN-159・160 が側選択規則を、MN-162 が交差許容＝背面通過の仕様決定 CO を、MN-163・164 が既存描画の回帰を、MN-165 がフィット境界の回帰をカバーする
- `dotnet build`・`dotnet test` 全緑と `tools/validate_master.py` 通過を併せて確認する
