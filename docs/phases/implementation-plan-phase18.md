## 1. スコープ

### やること

計算機の循環依存の扱いを拡張し、正味増循環を外部投入なしの定常解へ収束させる（仕様決定 AQ）。

- 展開中に循環依存（展開スタック上のアイテムの再要求）を検出したときの即時警告をやめ、検出パスとループゲインを記録する
- ループゲイン（検出パス上の隣接アイテムについて、次アイテムの入力量÷現アイテムの出力量の積）が 1 未満の循環を正味増とみなし、打ち切った残差を均衡化ループ内で解放・再展開して定常解を求める
- `CycleDetected` 警告の発行を、残差が解消できなかったアイテムに対して均衡化後の確定時に遅延して行う

### やらないこと

- 初期在庫（ブート投入量）の計算・出力（仕様決定 AR で対象外）
- 線形方程式による厳密解法への置き換え。既存の展開・引き戻しの帳簿をそのまま使う反復で定常解が得られるため採らない
- UI・グラフ・マスタデータの変更。本 Phase は計算結果が変わるだけで、要求行・警告の表示は既存のまま使う
- エンティティ可変化など remaining-issues の他項目

## 3. モデルの変更詳細

### 循環検出の記録（AQ）

需要展開の再帰中、展開しようとしたアイテムが展開スタック上にあれば循環依存とみなす点は従来どおり。
従来は警告を即時発行して残差を未充足へ計上していたが、本 Phase から警告を出さずに次を記録する。

- 検出パス: スタック上の、該当アイテムが最初に現れた位置から末尾までのアイテム列＋再要求アイテム（`i-a → i-b → i-a` など）
- ループゲイン: パス上の隣接アイテム対（X, Y）について、X の選択ペアのレシピで Y の入力量÷X の出力量を辺の比率とし、全辺の比率の積

記録はアイテム単位で検出ごとに管理する（ループゲイン・パス文字列・パス上でこのアイテムの直後に来る枝アイテム）。
同一パスの再検出は重複登録しない。警告時のパスは記録済み検出の最大ゲインのものを使う。
残差の未充足への計上は従来どおり行う（解放前の一時的な帳簿として扱う）。

### 解放反復（AQ）

`BalanceToFixpoint` の各ラウンドで、展開・引き戻しの後に解放ステップを実行する。

1. 循環検出の残っている未充足を持つアイテムのうち、ライブな循環がすべて正味増のものを需要登録順に解放する（未充足を 0 に戻し、そのアイテムを再展開する）。「ライブ」とは、検出パスでこのアイテムの直後に来る枝アイテムの需要が生産＋外部供給で余剰込みに賄われていないこと。枝アイテムが副産物余剰で賄われた検出は枝が死んだとみなして拒否権を持たない——その枝の正味減は発散の要因にならない。ライブな検出にゲイン 1 以上が 1 本でもあれば解放しない——解放してもその枝へ需要が戻り発散するため
2. 再展開では解放分に対応する追加生産が走り、循環内の再要求が再びスタック上で打ち切られ、おおよそゲイン倍の新しい残差が未充足へ積まれる
3. 正味増（ゲイン < 1）なら残差は反復のたびに幾何的に縮み、収束後の帳簿は外部投入なしの定常解と一致する
4. 1 回の解放ステップで循環由来の残差合計が縮まなかった場合は、解放と再展開の帳簿一式を解放前へ差し戻し（ロールバック）、以後の解放を打ち切る（複雑に絡む循環の保険）。差し戻しにより帳簿は解放しなかった計算と一致する。均衡化ラウンドの上限（100）も従来どおり共有する

ライブな枝にループゲイン 1 以上の循環が残るアイテムは解放しない。
解放しても残差が縮まず、解放のたびに生産量が膨らんで計画が歪むためで、従来の CYC 系テストの期待とも一致する。
副産物等で枝アイテムの需要が余剰込みに賄われた検出は枝が死んだとみなし、解放可否の判定から外す
（`Retract` で枝のレシピ稼働が消えた後に古いゲインが解放を阻害するのを防ぐ）。

### 警告の遅延発行（AQ）

`CycleDetected` 警告は検出時点では出さず、均衡化と追加需要の収束が終わった後、循環検出を記録したアイテムの未充足が残っていれば記録したパスで発行する。
採取上限超過の警告と同じ遅延発行パターンで、従来の `CycleDetected` は最終確定時の置き換えとなる。
解放で解消した循環と、後から届いた副産物で未充足が消えた循環には警告を出さない。

## 4. 暫定解釈

仕様協議で推奨採用が確定した枠組みの中で、実装詳細として次の暫定解釈を採る（PR 本文にも記録する）。

1. 解放はアイテム単位で行い、解放順は需要登録順（`DemandOrder`）で決定的とする
2. ループゲインの判定は計算機の既定の微小量（`Epsilon`）で切り、ライブな検出がすべて `ゲイン < 1 - Epsilon` であることを正味増とみなす
3. 循環内アイテムの要求量は従来どおり総需要（外部需要＋循環内消費を含む毛需要）で出力する。芽針なら炭塊向け＋種採り向けを合わせた量が `RequiredPerMinute` になる
4. 解放反復の上限は既存の均衡化ラウンド上限 100 を共有し、個別の反復上限は設けない
5. 同一アイテムに複数の検出パスが絡む場合、解放可否は検出単位で判定する。枝アイテムがまだ供給を要する（ライブな）検出がすべてゲイン 1 未満のときだけ解放する。部分解放（正味増分だけ解放する）はレシピの入力需要が全枝へ発生するため成立しない（Devin Review の指摘を受け確定）。副産物等で枝が死んだ検出はライブ判定から外れるため、除去・再計算は要らない（Devin Review 2 件目の指摘を受け確定）
6. 解放で残差合計が縮まなかったときは部分解放・部分適用ではなく、解放と再展開の帳簿一式を解放前へ差し戻す。解放しなかった計算と一致するため、ロールバックによる境界余剰での中途半端なラン増大を防ぐ（Devin Review 3 件目の指摘を受け確定）
