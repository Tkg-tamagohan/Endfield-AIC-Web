## 1. スコープ

### 背景と問題

Phase 39（仕様決定 CR）で双方向バリセンター掃引と交差数計測による最良候補採用を導入したが、同梱マスタの実計画で交差が残った（重息壌ガス目標で 2、重息壌目標で 3）。
残存の原因は、消費先が複数ランクに分かれるノード（息壌ガス・水）の下流バリセンターキーがランク項に支配され、局所的により良い配置へ動けない構造にある。
上流パスは先行を持たない採取ノードを「現位置維持」で動かせず、掃引は 3↔4 交差を振動して改善配置を一度も生成しないことを計測で確認した。

下流キーの消費先を隣接ランクに限定する変種は、報告箇所の交差を消す一方で別の交差 2 件（後退エッジ絡み・生産消費逆転）を新出させ、総数がほぼ変わらないことを実測で確認し、採用を見送った。
一方、採用順序に対して「ランク内の隣接ペアを入替え、全体の交差数が減る入替のみ採用する」後処理を 1 掃引だけ試したところ、両計画とも交差 0 に到達し、既存テスト 58 件も全件通過した（実測値の記録はユーザーへの整理書）。
仕様決定 CS で、この後処理（1 掃引限定の隣接交換）と、同率タイブレークの逆方向キー補強が確定した。
1 掃引限定の隣接交換は反復して全順序を動かす sifting とは別物であり、CR の「sifting 系は導入しない」方針とは抵触しないと判断された。

### やること

- 採用順序に対し、全ランクを昇順に 1 巡してランク内の隣接ペア（位置 i, i+1）の入替を順に試し、全体の交差数が厳密に減る入替のみ採用する後処理を追加する
- 後処理で環境供給設備（BM で配置されたノード）を含むペアは試行せず、入替ごとに BM の隣接挿入を再適用して隣接規則を維持する
- 掃引パスのランク内ソートでバリセンターキー同率のとき、Id 昇順の前に逆方向のバリセンターキー（逆方向に隣接を持たないノードは現位置）で再比較するタイブレークを追加する
- xUnit FG-63〜 と手動確認 MN-182〜 を実施する

### やらないこと

- 下流バリセンターの消費先範囲は変更しない（描画される全エッジの宛先・加重平均のまま。隣接ランク限定は実測で新出交差を伴い却下）
- 改善がなくなるまで繰り返す反復型の入替（sifting）は入れない。後処理は 1 掃引で打ち切る
- 層割り（BF〜BH・BM の層規則）・交差数の計測式・バリセンターの重み付け（CR の目標加重）・従来方式候補を含む最良候補採用の構造は変更しない
- `flow-graph.js`・`FlowGraph` コンポーネントなど JS・描画側は変更しない
- 表示方向（縦・横）や集約・台数分による順序の分岐はしない

## 3. 設計の詳細

### 3-1. 隣接ペア入替の後処理

最良候補を採用して `order` を確定した後（現行の `nodesByRank = bestByRank` の採用点）に、次の 1 掃引を行う。

- ランクを昇順（rank 0 から maxRank）に走査する
- 各ランクのノード列で、位置 i と i+1 の隣接ペアを左から右へ順に試す。i が受理・非受理に関わらず i+1 へ進み、ランク末尾まで継続する
- いずれかのノードが環境供給設備（BM で挿入された `envFixed` 対象）であるペアは試行しない
- 入替直後にそのランクへ BM の隣接挿入（`InsertDispensers`）を再適用し、`order` を更新してから全体の交差数を計測する
- 全体の交差数が現在の採用交差数より厳密に小さいときだけ受理し、採用交差数を更新する。同数または増加のときは入替前の並びへ復元する
- 全ランクの走査が終わった時点で打ち切る。反復はしない

試行の走査順（ランク昇順・ランク内は左から右）は受理結果に影響しうるため、仕様として固定する（暫定解釈。どの走査順でも「受理した入替は交差を減らす」の保証は変わらないが、結果の一意性のために順を定める）。
受理判定は交差数のみで行い、CR の第 2 キー（目標出力エッジの順序番号差）は後処理では見ない（暫定解釈。交差が減る入替が順序番号差を悪化させうるが、実害は軽微と判断した）。
交差数の計測式は CR と同一（ランク境界ごとの区間化＋順序位置の厳密な逆転対の計数）を使い、新しい計測を追加しない。

### 3-2. 逆方向キーによるタイブレーク

掃引パス（`RunPass`）のランク内ソートの比較を、方向キー → 逆方向キー → ノード Id（`StringComparer.Ordinal`）の 3 段へ改める。

- 方向キーは従来どおり、そのパス方向の隣接位置の加重平均（隣接なしは現位置）
- 逆方向キーは、逆方向の隣接位置の加重平均とする。上流パスでは下流キー、下流パスでは上流キーを使う。逆方向に隣接を持たないノードは現位置とする（従来の退縮規則と同じ扱い）
- 方向キー・逆方向キーがともに同率のときだけ Id 昇順を使う

タイブレークの適用は双方向掃引のパスのみとし、従来方式の候補を生成する評価パスは従来の比較規則（方向キーのみ、同率は Id 昇順）を維持する。
従来方式の比較規則まで変えると退化防止の比較基準自体が変わるため、従来方式側は改訂前のアルゴリズムどおりに保つ。

狙いは、単方向のキーが同率になるノード対（例: 消費先が共通の 2 アイテム）について、Id 昇順で割る前に反対側の隣接関係でもう一度比較し、上流の生産設備の並びと逆転する配置を抑えることである。
下流キーの実測例（rank 7 の息壌・赤銅圧力タンクの同率逆転）は消費先限定の変種でのみ出たものだが、同型の同率は消費先全域でも起き得るため、補強として入れる。

### 3-3. 確定的動作と退化防止

- 走査順・比較キー・受理条件はすべて入力に対して一意で、結果は決定的である
- 後処理が受理する入替は交差数を厳密に減らすものだけなので、後処理後の交差数は掃引採用時を上回らない。従来方式候補を含む最良候補採用（CR の退化防止）と合わせて、採用順序の交差数が従来を上回らない構造は維持される
- 計算量はランク数 × ランク内ペア数 × 交差計測（境界×エッジ対）の積で、本規模（ノード数十個・エッジ数十本）では素朴な実装で十分である（暫定解釈）

### 3-4. 既存規則の維持

- BM の散布機隣接挿入は入替ごとに再適用し、環境供給設備自体は入替対象外とするため、散布機が利用設備の隣に置かれる規則は後処理を通じて維持される
- 同率 Id 昇順・全表示での共通モデル・交差数計測の非公開性は不変
- 後処理はモデル内部の順序だけを変え、`FlowGraphModel` の公開面は増やさない

## 4. 受け入れ条件

- 同梱マスタの重息壌ガス・重息壌を目標とする計画で、Phase 39 で残った供給エッジの交差（息壌ガス×不活性ガス、水→天有洪炉）が解消される
- どんな計画でも採用順序の交差数が従来方式を上回らない
- BM の隣接規則・同率 Id 昇順・全表示での共通モデル・決定性が維持される

## 6. リスクと引き継ぎ

- 後処理は局所探索であり、交差が残るグラフはあり得る。同梱マスタの 2 計画で 0 交差に到達したのは実測値であり、一般の保証ではない
- 後処理の受理判定は交差数のみを見るため、交差が減る入替が CR の第 2 キー（目標と設備の近接）を悪化させうる。実害が出た場合は受理判定に第 2 キーの同数制約を加える改訂を検討する
- 走査順（ランク昇順・左から右）を変えると受理結果が変わりうる。順の選定自体に意味はなく、一意性のための固定である（暫定解釈として仕様に明記済み）
- 採番は並行セッションと衝突しうる。push 前に main の `decision-records.md`・テスト仕様書の最新番号を再確認する
