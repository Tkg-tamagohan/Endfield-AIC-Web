## 1. スコープ

### やること

- 表示方向の横・縦切替を追加し、既定を縦とする（仕様決定 BJ）。縦表示は rank（層）を行・order を行内の横位置へ転置し、物の流れを下から上（目標アイテム=最上行）とする
- 領域下端のドラッグハンドルで高さを任意に変更でき、最大化ボタンで画面全面へ広げられるようにする（仕様決定 BK）
- ピンチ（2 点タッチ、中点アンカー）による拡大縮小と、画面上の＋・−・フィットボタンを追加する（仕様決定 BL）。`touch-action: none` を領域全体とノードへ広げ、ズーム下限を 0.2 へ緩和する
- ヒント文言をタッチ操作に対応した表現へ更新する

### やらないこと

- 層割り（BF〜BH）・エッジ種別・容量超過判定（AN）・粒子密度（AP）などのモデル側仕様の変更。`FlowGraphModelBuilder` と Domain、WGSL シェーダは不変とする
- ダブルタップズーム・パン範囲の制限（迷子はフィットボタンで復帰させる）
- 切替状態・高さの永続化（localStorage を使わず、既存トグルと同じくセッション内保持）
- リスト表示側・計算ロジックの変更

## 3. 描画の変更詳細

### 表示方向の転置（BJ）

表示方向（縦=既定・横）は `CalculatorPanel` が保持し、`FlowGraph` のパラメータ経由で update 呼び出しのたび JS へ渡す（§4-4）。切替時はノード座標を再計算して fitView を再適用する。

縦配置は横配置の転置で実装する。

- rank→行。行の高さはその rank に含まれるノードの最大高。rank 0（採取側の最深）を最下行、実在する最大 rank の行を最上行とする
- 層割り対象外の終端ノード（散布機など出力のない設備、仕様決定 BH）は最深消費アイテムの rank+1 の行に置く（横表示の「1 列右」の転置）。消費先が Layer0 のときは目標アイテムの 1 行上に来るため、「Layer0=最上行」は層割り対象のアイテム行を指すものとする
- order→行内の横位置。左から順に `NODE_GAP_X` 間隔で並べ、各行は最大行幅に対して水平方向へ中央寄せする。行間は `NODE_GAP_Y`
- ノードは行内で上辺揃えにする（横配置で列内を左辺揃えにしている規則の転置）。下辺は高さ差で不揃いになるが、接続点は各ノードの実測した下辺中央を指すため問題ない

エッジの接続点は方向ごとに次の規則とする。エッジごとのポート割り当てはなく、同一ノードの全エッジは接続点を共有してベジェ曲線で扇状に分岐する（現行どおり）。

- 縦: 出口はソースノードの上辺中央 `(x + w/2, y)`、入口はターゲットノードの下辺中央 `(x + w/2, y + h)`。制御点は垂直方向へ `max(36, 距離×0.5)` 張り出す
- 横: 現行どおり。出口は右辺中央、入口は左辺中央、制御点は水平方向
- 循環を閉じる後退エッジも同一規則で描き、縦表示では上側ノードから下側ノードへ側面に膨らむループとして見える（横表示で右から左へ戻る描き方と同型）
- 隣接ノードは層割り規約上 1 層以上離れるため、同一行同士のエッジは発生しない

縦表示でのノード間隔（`NODE_GAP_X`・`NODE_GAP_Y` の転置後の見え方）と粒子密度（`PARTICLE_COUNT_MIN`・`PARTICLE_COUNT_MAX`・`PARTICLE_SATURATE_PER_MINUTE`）の調整値は未定とする。実装時に暫定値を置いて見た目を確認し、テスト実施の前にユーザーへ調整内容を確認する（AGENTS「欠けている情報を勝手に埋めない」に従い、値は確定しないまま持ち越す）。

### 高さ調整と最大化（BK）

`.flow-graph-wrap` の高さを固定値から状態値へ変える。既定は現行値（420px、モバイル幅 300px）、ハンドルのドラッグで変更し、下限は既定値・上限はなしとする。

- ハンドルは領域下端中央のグリップとし、pointerdown から move で wrap の高さを更新する。ポインター操作のためタッチでも動く。`ResizeObserver` が canvas バッファを追従させ、ビューの拡大率と位置は維持する（refit しない）
- 最大化ボタンは wrap を `position: fixed` のオーバレイへ切り替える方式とする。Fullscreen API を使わず CSS で実現し、ブラウザ間の差異を避ける。復帰は最大化ボタンの再押下または Esc キーとし、展開中も高さ調整・パン・ズームは有効とする
- 最大化中はページ本体のスクロールを抑止する

### タッチズームとボタン（BL）

領域上のアクティブポインターを `Map` で管理し、1 点はパン（現行のドラッグ操作）、2 点はピンチとする。

- 2 点目が触れた時点でパンからピンチへ移行し、初期の 2 点間距離と中点を記録する。距離比で拡大率を更新し、中点の移動量をそのままパンへ加算する
- 拡大率の更新はホイールと同じくアンカー（ピンチ中点）を固定して `view.s` を変える方式で、`ZOOM_MIN` は 0.2、`ZOOM_MAX` は 1.5（仕様決定 AL のアイコン原寸制約）とする
- `touch-action: none` を `.flow-graph-wrap` と `.fnode` に適用する。canvas のみの適用ではノード上から始まる操作がブラウザ既定のページズームやスクロールへ流れるため、領域内のタッチ操作をグラフへ一元化する
- ズームボタン群（＋・−・フィット）は領域内右上に常時表示する。＋・−は領域中心をアンカーに段階的に拡大縮小し、フィットは `fitView` を実行する。ピンチに気づかない利用者と、ホイールのない環境への代替を兼ねる
- パン範囲は従来どおり無制限とし、迷子はフィットボタンで復帰させる

### ヒント文言

「ドラッグで移動、ホイールで拡大・縮小できます。」を、ピンチを含む表現へ更新する（「ドラッグで移動、ピンチまたはホイールで拡大・縮小できます。」）。

## 4. 確定した UI 上の判断

実装中に変更する場合は本節を更新する。

1. 横⇄縦切替はグラフ領域のツールバー行に置き、グラフ表示中のみ見せる（BJ で採用。既定=縦）
2. 縦表示の流れは下から上とし、目標アイテムを最上行に置く（ユーザー決定。横表示の左から右を反時計回りに回転した形）
3. 最大化は Fullscreen API ではなく `position: fixed` のオーバレイで実現する（iOS でも同一動作にするため）
4. 表示方向・高さ・最大化は `CalculatorPanel` が状態として保持し、`FlowGraph` へパラメータとして渡す。グラフ⇄リスト切替で `FlowGraph` が再マウントされても設定は維持される（BJ・BK の「セッション内のみ保持」は同じ計算ページ内の表示切替をまたいでも有効、と解釈）。localStorage は使わず、ページを離れたときは既定へ戻る

## 5. テスト

[test-specification-phase24.md](test-specification-phase24.md) に従う。
`FlowGraphModelBuilder` は不変のため xUnit の追加は原則不要とし、`dotnet test` 全緑の回帰確認を行う。
描画側の検証は WebGPU 対応 Chrome と CDP による E2E で行い、ピンチは `Input.dispatchTouchEvent` の合成で確認する（検証手順は `webgpu-blazor-ui-testing`・`testing-blazor-apps-flow-graph` の各スキルに従う）。
ブラウザプレビューによるユーザー確認は実装後に別途挟む（ui-mock-first ルール）。

## 6. 受け入れ条件

- 既定で縦方向のグラフ（原料=下、目標=最上行）が描画され、横への切替で従来表示へ戻る
- 下端ハンドルのドラッグで高さを変えられ、最大化ボタンで全面オーバレイへ展開・復帰できる
- ピンチと画面上のボタンで拡大縮小でき、ノード上から始まる操作もページズームやスクロールへ流れない
- 公開 App と管理ツール計算プレビューの双方で同一動作になる（共有 RCL のため）
- `dotnet build` と `dotnet test` が全緑である
