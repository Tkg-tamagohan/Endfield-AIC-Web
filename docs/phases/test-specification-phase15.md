## 2. 自動テスト項目

`FlowGraphModelBuilder` の純粋関数を対象とする。フィクスチャは `ApplicationFixtures` のヘルパーで構築し、同梱マスタには依存しない。
前提となるシナリオは「採取→精錬→目標」の最小チェーンと、複数経路・環境設備・未充足・余剰を含む計算結果である。

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| FG-01 | 目標アイテムはフラグ付きノード | 目標に指定したアイテムを含む計画 | `item:<ItemId>` ノードが存在し目標フラグが立つ |
| FG-02 | 採取供給は共通ノードへ | Gathered 供給を持つ計画 | `gather` ノードが 1 つだけあり、採取供給量ぶんの Gathered エッジで対象アイテムへ接続する |
| FG-03 | 設備ノードは FacilityId で集約 | 同一設備で複数レシピを回す計画 | `fac:<FacilityId>` ノードが 1 つで、各レシピの入出力エッジがそのノードに接続する |
| FG-04 | 同一ノード対のエッジは合算 | 同じ設備への入力が 2 種の数量で現れる計画 | 始点・終点・種別が同じエッジは流量を合算した 1 本になる |
| FG-05 | 副産物出力のフラグ | `SortOrder > 0` の出力を持つレシピを回す計画 | その RecipeOutput エッジに副産物フラグが立つ |
| FG-06 | 環境消費は専用エッジ | 散布機を持つ計画 | EnvironmentConsume エッジが `item:<ConsumeItemId>` → 供給設備ノードへ、流量 `ConsumeRatePerMinuteTotal` で接続する |
| FG-07 | 固定消費は切上げ台数を掛ける | 固定消費ペアを持ち設備が切上げ 2 台の計画 | FixedConsumption エッジの流量が `RatePerMinute × 2` になる |
| FG-08 | 層割りは最長パス | 採取→設備 A→中間アイテム→設備 B→目標の計画 | 採取ノード rank 0、設備 B が設備 A より大きい rank を持つ |
| FG-09 | 循環経路で停止する | 相互依存の残存経路を含む計画（CycleDetected 警告あり） | `Build` が有限時間で返り、後退エッジを無視したランク付きモデルが返る |
| FG-10 | 未充足アイテムのフラグ | 未充足を持つ計画 | 対応する `item:` ノードの `UnmetPerMinute` が正の値を持ち、そのノードが rank 0 近辺の起点側に置かれる |
| FG-11 | 余剰のみのアイテムもノード化 | 副産物のみで登場するアイテムを含む計画 | `ItemRequirements` にないアイテムにも `item:` ノードがあり余剰量を持つ |
| FG-12 | 未調整ビューは倍率を掛ける | 切上げ台数が実数台数より大きい計画で `unadjusted=true` | RecipeInput・RecipeOutput の流量が `ResultViewBuilder` と同じ倍率で拡大され、`unadjusted=false` と一致しない |
| FG-13 | 輸送容量超過の判定（Phase 17 の仕様決定 AN で判定対象を設備ユニット入力へ改訂。新期待は [test-specification-phase17.md](test-specification-phase17.md) §1 を参照） | 設備 1 ユニットへの入力流量が輸送容量を超えるアイテム | 超過した入力エッジと両端ノードに容量超過フラグが立つ |
| FG-14 | 空の計画 | `ItemRequirements`・`RecipeRuns` が空の計画 | 例外を投げず、採取ノードを含まない空モデルが返る |

razor の UI 状態遷移（切替ボタン、ノードクリックのスクロール）と canvas の描画内容は bUnit・WebGPU テスト基盤を持たないため対象外とする（remaining-issues.md「Razor ページ内 UI 状態遷移のテスト空白」に同種の空白を記録済み）。
`dotnet test` は回帰確認として全件実行し、全緑であることを受け入れ条件とする。

## 3. 手動確認項目（ブラウザプレビュー）

実装のブラウザプレビューをユーザーに操作してもらい、次を確認する。
公開アプリでゴールデンパス（結晶外殻 60/分）を実行してグラフを表示する。

| ID | 確認内容 |
|---|---|
| MN-37 | 計算実行後にグラフ節が表示され、採取→設備→アイテムが左から右へ層状に並ぶ |
| MN-38 | エッジ上を粒子が流れ、流量の大きいエッジほど粒子が多い・速い |
| MN-39 | ノードをクリックするとリストの対応行へスクロールして強調される |
| MN-40 | ドラッグでパン、ホイールでカーソル中心にズームでき、アイコンが粗くならない程度に拡大が止まる |
| MN-41 | 「未調整／調整済」「毎分／毎秒／期間」の切替にグラフの流量表示が追従する |
| MN-42 | グラフ切替ボタンで非表示にできる。再度表示すると直前の内容が再描画される |
| MN-43 | ウィンドウ幅をスマートフォン相当へ狭めるとグラフが既定で折りたたまれ、リストだけが見える |
| MN-44 | 未充足や容量超過がある計算で、該当アイテムノードが赤系に強調される |

WebGPU 非対応環境（フラグなしの Firefox 等）でのフォールバックは、CI 環境では確認できないため開発環境での確認とし、確認できた場合は MN-45 として記録する。

| ID | 確認内容 |
|---|---|
| MN-45 | WebGPU 非対応ブラウザではグラフ節と切替ボタン自体が出ず、リスト表示のみになる |

## 4. 受け入れ条件との対応

- `dotnet test` 全緑、`validate_master.py` 通過: §2 の回帰確認で担保
- グラフの描画・追従・フォールバック: §3 のユーザー確認で担保
- FG-08〜FG-10 が、層割りと循環耐性を実装意図どおりに固定する
