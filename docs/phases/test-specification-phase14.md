## 2. 自動テスト項目

`ItemCatalog` の純粋関数を対象とする。フィクスチャはカテゴリの異なるアイテム数件で構成でき、同梱マスタには依存しない。

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| IC-01 | カテゴリ列挙の重複除去 | 「鉱物」「部品」「鉱物」を持つ 3 アイテム | `Categories` が「鉱物」「部品」を初出順で返す |
| IC-02 | 空カテゴリの除外 | `Category` 空のアイテムを含む集合 | `Categories` が空値を含まない |
| IC-03 | 未絞り込みは全件 | `FilterByCategory` に null と空文字 | いずれもアイテム全件を返す |
| IC-04 | カテゴリ一致のみ抽出 | 「鉱物」を指定 | そのカテゴリのアイテムだけを返す |
| IC-05 | 現在値の保持（絞り込み外） | 「部品」のアイテムを持つ行で「鉱物」に絞る | `OptionsForSelection` が部品アイテムを末尾に含む |
| IC-06 | 現在値の保持（絞り込み内） | 「鉱物」のアイテムを持つ行で「鉱物」に絞る | 現在値が重複して追加されない |
| IC-07 | 現在値が未選択 | `currentItemId` が null または空 | 絞り込み結果のみを返す |

razor の UI 状態遷移（datalist の候補表示、絞り込み select の切替動作）は bUnit 未導入のため対象外とする（remaining-issues.md「Razor ページ内 UI 状態遷移のテスト空白」）。
`dotnet test` は回帰確認として全件実行し、全緑であることを受け入れ条件とする。

## 3. 手動確認項目（ブラウザプレビュー）

実装のブラウザプレビューをユーザーに操作してもらい、次を確認する。
Admin ホームでマスタを読み込み、ナビの「アイテム」と「レシピ」で確認する。

| ID | 確認内容 |
|---|---|
| MN-32 | アイテム編集のカテゴリ欄で、フォーカスまたは入力に応じて文書内の既存カテゴリが候補に出る。候補にない新しい文字列も確定できる |
| MN-33 | レシピ編集で「アイテム絞り込み」からカテゴリを選ぶと、入力、出力、固定消費の選択肢がそのカテゴリのアイテムだけになる |
| MN-34 | 絞り込み中に、条件に合わないアイテムを選んでいた行が末尾に現在値を残し、別アイテム表示に化けない |
| MN-35 | 「すべてのカテゴリ」へ戻すと選択肢が全アイテムに戻る |
| MN-36 | 絞り込み中に入力行や出力行を追加する、または固定消費を有効にすると、既定値が絞り込み後の先頭アイテムになる |
