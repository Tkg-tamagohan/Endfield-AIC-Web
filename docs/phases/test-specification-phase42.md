## 1. モデル検査（xUnit）

### 基礎素材指定の計算（BAS）: BaseMaterialTests.cs（新規）

フィクスチャは `CalculationFixtures` に中間素材（レシピ成果物かつ非採取）を含む多段レシピ構成を持たせて組み立てる。ゴールデン値はフィクスチャ定義から検算して記述し、実装から逆引きしない。

| ID | 内容 | 条件 | 期待 |
|---|---|---|---|
| BAS-01 | 指定アイテムは外部調達となり上流を展開しない | 多段チェーンの中間素材を指定 | 指定アイテムの `ItemRequirement` に新供給種別の全量が計上され、そのアイテムを産出する `RecipeRun` がなく、上流アイテムの需要・ランが出ない |
| BAS-02 | 上流の設備・電力・環境が計上されない | BAS-01 の構成 | 上流設備の `FacilityRequirement`・`TotalPowerConsumption`・環境要件が指定分だけ減る |
| BAS-03 | 副産物充当の残差のみ外部調達 | 指定アイテムが他ランの副産物でも産出される構成 | 供給に `Byproduct` と新種別が併存し、新種別は残差分のみになる |
| BAS-04 | 複数指定 | 2 つの中間素材を指定 | 両者が外部調達となり、互いの経路が残らない |
| BAS-05 | 指定なしの回帰 | 同構成で指定なし | 従来どおりの展開・供給となる（`Gathered` 種別の扱いも据置） |
| BAS-06 | イベント非有効の指定アイテムは X 優先 | 非有効イベント限定のアイテムを指定 | 外部調達は計上されず、従来どおり未充足＋警告のまま |
| BAS-07 | 指定を介した循環の解消 | 指定アイテムを介する循環（A→B→A で B を指定） | B は外部調達となり循環警告が出ず、A は通常展開で収束する |
| BAS-08 | 指定アイテムのペア上書きは効果なし | 指定アイテムに `PairOverride` を渡す | ランは登録されず、エラー・警告も出ない |
| BAS-09 | 固定消費・環境消費由来の需要も外部調達 | 指定アイテムが固定消費または環境消費の対象でもある構成 | それらの需要分も新種別で計上される |
| BAS-10 | 目標の直接入力を指定 | 目標アイテムの入力の中間素材を指定 | 目標側のランは残り、指定アイテムは外部調達。設備台数は目標ラン分のみになる |
| BAS-11 | 計画に登場しない指定は効果なし | 需要のないアイテム Id を指定集合に入れる | 計画は指定なしと同一になり、例外・警告は出ない |
| BAS-12 | 指定アイテムの余剰は処理対象になりうる | 指定アイテムが副産物で余剰を持ち、処理レシピが適格な構成 | 余剰は処理ランで消費される（供給側の省略と消費側の処理は独立） |

## 3. 手動確認項目（ブラウザプレビュー）

同梱マスタまたは Admin の編集経路で中間素材を含む計画を出して確認する。実装のブラウザプレビューをユーザーに操作してもらい、確認後に実施する。
fixture 注入が必要な場合は fixture-injection-blazor-testing スキルに従う。

| ID | 確認内容 |
|---|---|
| MN-191 | 中間素材の素材行で基礎素材トグルを ON にすると、そのアイテムの合成経路（上流の設備・採取）が計画とグラフから消え、素材行が「外部調達 N」になる |
| MN-192 | 複数アイテムの指定が併存し、OFF で元の経路へ戻る |
| MN-193 | 目標・採取素材の行にトグルが出ず、指定済みアイテムを目標に追加すると指定が外れる |
| MN-194 | グラフで指定ノードが青系になり、メタ行に「外部調達 N」が出る。目標の橙枠・未充足の赤枠・処理の紫との併用表示を確認する |
| MN-195 | 指定を保持したまま目標数量やマップを変えても指定が維持される。計画から外れた指定は行が消えても、再登場で復帰する |
| MN-196 | 管理ツールの計算プレビューでも同様に指定・表示される |
| MN-197 | 指定アイテムの素材行でペア代替ドロップダウンが出ない |
