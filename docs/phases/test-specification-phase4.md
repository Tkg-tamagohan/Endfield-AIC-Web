# Phase 4 テスト仕様書

**対象**: Phase 4 成果物（Application 層のユースケース・表示導出、および計算アプリ UI）
**前提ドキュメント**: [requirements.md](../requirements.md)、[decision-records.md](../decision-records.md)、[implementation-plan.md](../implementation-plan.md)、[implementation-plan-phase4.md](implementation-plan-phase4.md)

> 項目 ID は `分類-連番` で採番し、要件との対応をトレースできるようにする。

## 1. テスト環境と実行方法

| 項目 | 内容 |
|---|---|
| 自動テスト基盤 | xUnit。`tests/EndfieldAicWeb.Application.Tests` に配置（ソリューションへ追加） |
| テストデータ | コード上で `MasterDataSnapshot`・`MasterDocument` のフィクスチャを構築する（Domain.Tests の CalculationFixtures と同じ方式）。`data/master.json` からの往復は Infrastructure.Tests が担保済みのため扱わない |
| 実行コマンド | `dotnet test` |
| 実行環境 | Linux。CI（ubuntu-latest）でも実行される |
| 手動確認 | App を `dotnet run` で起動し、ブラウザプレビューで §5 の項目を確認する（ui-mock-first ルールに従い、ユーザー確認を先に取る） |

## 2. フィクスチャ定義

### A-01: 単純チェーン

`i-ore`（採取素材）×2 → `i-part` を `r-part`（設備 `f-asm`、4 秒、ペアは 4 秒環境なしと 3 秒 `env-gas` の 2 行）で生産する。`env-gas` は `f-disp` が `i-gas`（採取素材）を 360 個/分 消費する。`f-asm`・`f-disp` の消費電力は 50・20。

### A-02: 切上げ発生

`i-u`（採取素材）×4 → `i-t` を `r-t`（`f-t`、2 秒）で生産。目標 72 個/分で実数 2.4 台 → 切上げ 3 台となり、未調整で過剰が出るケース。

### A-03: 共有設備

同一設備 `f-sh` 上に 2 ラン（`r-x`・`r-y`、ともに 4 秒・出力 1）が乗り、実数合計が非整数になるケース。

### A-04: 代替レシピとイベント

`i-x` を出力するレシピが複数（常設の旧版・新版とイベント限定版）あり、`env-ltd`（非有効イベント `ev-off` 所属）を要するペアが混在するケース。選択規則・適格判定の確認に使う（Domain.Tests F-03 と同趣旨）。

### A-05: イベント不可アイテム

`i-ltd`（非有効イベント `ev-ltd` 所属）を副産する常設レシピがあるケース。余剰の全量計上を確認する（Domain.Tests F-12 派生と同趣旨）。

## 3. テスト項目一覧（Application 層）

### SNP: スナップショット生成

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| SNP-01 | 文書からスナップショットを作る | A-01 相当の `MasterDocument` | Items・Facilities・Environments・GameEvents・Recipes が転写される |
| SNP-02 | 索引が使える | 同上 | `ItemsById`・`RecipesByOutputItemId` 等で Id 引きできる |

### OPT: ペア候補の列挙

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| OPT-01 | 適格候補の平坦化 | A-01 の `i-part` | 2 ペア行が候補になる。`env-gas` つき行には環境の識別がある |
| OPT-02 | 既定候補の識別 | A-01 の `i-part` | CycleTime 最小のペア行のみ `IsDefault` |
| OPT-03 | 非有効イベントの除外 | A-04 の `i-x`（`ev-off` 非有効） | イベント限定レシピと `env-ltd` ペアが候補に出ない |
| OPT-04 | 候補なし | 採取素材・レシピを持たないアイテム | 空リスト |
| OPT-05 | キーから上書きへの変換 | OPT-01 の各候補 | `PairOverride` の全要素（RecipeId・FacilityId・CycleTime・EnvironmentId・FixedConsumption）が一致して復元される |

### SVC: 計算サービス

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| SVC-01 | 計算の実行 | A-01・目標 `i-part` 60/分 | `ProductionPlan` が返り、素材・設備・環境・電力が埋まる |
| SVC-02 | 需要アイテムごとの候補マップ | 同上 | 需要のあるアイテムに候補リストが対応づく（候補のない行は空・キーなし） |
| SVC-03 | 上書きの反映 | A-01・`i-part` の上書きを環境ペアへ | 確定ペアが上書き側になり、散布機が計上される |

### VW: 結果ビュー（調整済）

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| VW-01 | 素材行の展開 | SVC-01 の結果 | 行に要求量・供給内訳（種別＋流量）・未充足が入る |
| VW-02 | 設備行と推奨制限 | A-02・目標 `i-t` 72/分 | 実数 2.4 → 切上げ 3。調整済では `i-u` の推奨流量制限が行内に出る |
| VW-03 | 環境行 | A-01・環境ペア選択 | 台数・消費アイテム・消費流量（個/分）が入る |
| VW-04 | 余剰・警告の転写 | A-02 | 調整済の余剰は計算結果どおり（切上げ過剰を含まない） |
| VW-05 | 未調整での推奨制限 | A-02 | 未調整ビューでは流量制限行を出さない |

### VWU: 未調整表示の導出

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| VWU-01 | 単一設備のスケール | A-02・目標 `i-t` 72/分 | 倍率 = 3/2.4 = 1.25。素材のレシピ供給が ×1.25、余剰に過剰分が出る |
| VWU-02 | 共有設備の倍率 | A-03 | `s = 切上げ合計 / 実数合計` を両ランへ掛け、供給が同一倍率で増える |
| VWU-03 | 散布機の除外 | A-01・環境ペア選択 | 倍率の分母から散布機台数を除く。散布機の消費・台数はスケールしない |
| VWU-04 | イベント不可アイテムの余剰 | A-05 | 未調整で全量が余剰になる（供給としては扱わない） |
| VWU-05 | 採取素材はスケールしない | A-02 | 採取素材の供給量は未調整でも需要どおり |

### EVT: イベント自動有効化（[test-specification-phase2.md](test-specification-phase2.md) §EVT の EVT-01〜05（Domain のイベント限定アイテム）とは同番号の別対象）

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| EVT-01 | 開催期間中のイベント | ActiveFrom/ActiveTo が今日を含む | 既定で有効（IsActiveByDefault = true） |
| EVT-02 | 期間±1 日の猶予 | 今日が ActiveFrom-1 日・ActiveTo+1 日 | それぞれ既定で有効。猶予の外側では無効 |
| EVT-03 | 常設イベント | ActiveFrom/ActiveTo ともに未設定 | 常に既定で有効 |
| EVT-04 | 終了・未開催イベント | 期間外（猶予込みで含まない） | 既定では無効（折りたたみ選択の対象） |
| EVT-05 | 表記違いの同一瞬間 | 同一瞬間の `Z` 表記とオフセット変換後の値 | 同一の判定結果（仕様決定 Z） |

### EVI: イベントチェックの既定管理

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| EVI-01 | 期間内イベントの初期化 | 開催中のイベント | Checked・IsActiveByDefault が true |
| EVI-02 | 期間外イベントの初期化 | 終了済みのイベント | Checked・IsActiveByDefault が false |
| EVI-03 | 初期化の順序保持 | 複数イベントの入力 | 入力順のまま自動有効判定を保持 |
| EVI-04 | 既定の再評価 | 期間終了後の日付で再評価 | 未操作チェックは既定へ追従、操作済み（Touched）は保持 |

### FIL: アイテム検索

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| FIL-01 | 空クエリ | ""・空白 | 全件が返る |
| FIL-02 | 名前の部分一致 | 名前の一部分 | 該当アイテムのみ返る（大文字小文字を区別しない） |
| FIL-03 | Id の部分一致 | Id の一部分 | 該当アイテムのみ返る |
| FIL-04 | 不一致 | 存在しない文字列 | 空リスト |
| FIL-05 | 選択解除判定 | 選択済み名と検索本文の一致/不一致 | 不一致なら解除、一致・未選択なら維持 |

FIL-01〜04 は `ItemSearch` の呼び出し元が Phase 20（アイテム選択の改修）で消滅し、`ItemSearchTests` が Phase 22-2（仕様決定 BB〜BE）で削除されたため廃止項目である。
FIL-05 は選択解除判定として `ItemDeselectTests`（CalculationInputBuilderTests.cs）に現存する。
[test-specification-phase19.md](test-specification-phase19.md) §2 の FIL-05〜07（`ItemSearch` のカテゴリ絞り込み）は同番号の別対象で、実装は削除済みである。

### ECN: 散布機台数入力

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| ECN-01 | 有効台数の変換 | 整数の台数・空欄行 | EnvironmentCountOverride になり、空欄は無視 |
| ECN-02 | 上限ちょうど | 台数=自動検出の上限 | 受理 |
| ECN-03 | 不正台数 | 非整数・負・上限超過 | エラー（環境名と上限を含む） |

### PRD: 期間換算・表示単位

| ID | 内容 | 入力 | 期待 |
|---|---|---|---|
| PRD-01 | 合計分数の組み立て | 1 日・2 時・30 分 | 1440 + 120 + 30 = 1590 分 |
| PRD-02 | 不正入力 | 負・非有限値のいずれかを含む | 無効として扱う（期間換算しない） |
| PRD-03 | 換算係数 | 個/分の値 | 毎分 = そのまま、毎秒 = ÷60、期間 = ×合計分数 |
| PRD-04 | 換算の対象外 | 消費電力・推奨流量制限 | いずれの単位でも値が変わらない（仕様決定 M） |

## 4. 受け入れ条件との対応

- 全項目緑であること。
- SNP・OPT・SVC で計算入口のユースケースが文書どおりに動くことを確認する。
- EVT で仕様決定 T のイベント自動有効化（期間±1 日・常設・期間外）を確認する。
- FIL で約 200 件を想定したアイテム検索の絞り込みを確認する。
- VW・VWU で仕様決定 O の 2 状態表示の導出規則を確認する。
- PRD で仕様決定 M の期間換算を確認する。

## 5. 手動確認項目（ブラウザプレビュー）

実装のブラウザプレビューをユーザーに操作してもらい、次を確認する。ユーザーのフィードバックを反映してから §3 のテスト作成に進む。

| ID | 確認内容 |
|---|---|
| MN-01 | マスタ JSON が読み込まれ、生産リストのアイテム候補が出る |
| MN-02 | 行の追加・削除と目標入力で計算が実行され、素材・設備・電力が出る |
| MN-03 | 期間内イベントは自動で ON、期間外は折りたたみから選択でき、切替でイベント限定レシピ・アイテムの扱いが変わる |
| MN-04 | 結果の環境行で散布機台数を下げると即時再計算される。空欄は自動値、上限超えはエラー |
| MN-05 | 素材行のペア選択変更で即時再計算される。環境の有無が候補表記から分かる |
| MN-06 | 未調整／調整済の切替で余剰と推奨流量制限の表示が変わる |
| MN-07 | 期間入力で個数換算が表示され、電力・流量制限は換算されない |
| MN-08 | スマートフォン幅で入力・結果が 1 列に落ち、操作が潰れない |
| MN-09 | 非公式ファンツールの明記が見える。不正入力（空行・非数値）がエラー表示になる |
| MN-10 | アイテム検索で絞り込んで選択できる。選択済み名を編集すると選択が解除される |

MN-10 はテキスト検索コンボを前提とする項目で、Phase 20（仕様決定 AU）でアイテム選択がカテゴリ・アイテムの select ペアへ替わったため手動確認の対象外である。
絞り込み・選択の確認は [test-specification-phase20.md](test-specification-phase20.md) の MN-62・MN-63 に移り、選択解除判定 `ShouldDeselectItem` は UI 呼び出し元を持たず `ItemDeselectTests`（CalculationInputBuilderTests.cs）のみで担保する。
