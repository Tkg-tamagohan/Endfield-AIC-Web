### 環境設備の層（BM）: FlowGraphModelBuilderTests

| ID | 内容 |
|---|---|
| FG-38 | 環境供給設備は利用設備の最小層に置かれる。散布機のみ出力を持たない構成（従来 FG-31 のフィクスチャ）で、`fac:f-disp` の層が利用設備 `fac:f-a` の層と一致し、消費アイテム `item:i-gas` はその直上流（層+1、rank−1）になる。FG-31 をこの契約へ書き換える |
| FG-39 | 複数の利用設備では最小層に置く。環境を要求するランが浅い経路と深い経路の両方の設備にあるとき、散布機は浅い側（層番号が小さい側）の利用設備と同じ層になる |
| FG-40 | 1 台の供給設備が複数環境を担うとき、全環境の利用設備を合わせた最小層に置く |
| FG-41 | 台数分表示（expandFacilities）では、散布機ユニットは自分の `DispenserEnvironmentId` を要求するランを占有するユニットの最小層に置く |
| FG-42 | 利用設備が 0 件の環境では従来規則へ退避し、最深消費アイテムの直下流に置く。計算機ではこの構成は生成されない（散布機台数は稼働中ランの環境にのみ計上されるため、上書きのみの環境は計画に現れない）。手組みの `ProductionPlan` で防御的退避を検査する |
| FG-43 | ランも回す兼用設備は出力を持つため本規則の対象外で、従来どおりの層割りになる |
| FG-44 | 環境設備の消費アイテムは設備を消費者に含めた再層割りで設備層+1 以降になり、ガス→散布機エッジが順方向（上流→下流）を保つ。消費アイテムの生産設備もさらに上流へ来る |
| FG-48 | 同じ層に無関係な設備が並ぶときも散布機は利用設備の隣に置く。行内順のソートキーは利用設備の位置へ吸着させる（Review 指摘への回帰） |
| FG-49 | 環境利用レシピがその環境の消費アイテムを副産物として産出するときも、散布機は利用設備と同じ層を保つ。自己供給の出力エッジは再伝播対象外として後退エッジに残す（Review 指摘への回帰） |

| ID | 内容 |
|---|---|

## 2. 手動確認項目

E2E 検証は WebGPU 対応 Chrome で行う。
緑化・層位置・ラベルの確認は CDP の DOM 検査（クラス・ノード位置・テキスト）で客観的に確認し、見た目はスクリーンショットで記録する。
環境を要求するレシピと複数設備の経路は、実マスタ（息壌の安定環境・炭塊の 2 経路）または Admin の編集 UI で文書内データを作って検証する（`admin-driven-fixture-blazor-testing`・`fixture-injection-blazor-testing` の手順に従う）。

| ID | 対象 | 条件 | 期待 |
|---|---|---|---|
| MN-100 | 環境設備の層 | 環境を要求するレシピを含む計画をグラフ表示 | 散布機が利用設備と同じ行（縦表示）に並び、目標行より上に浮かない。ガス→散布機のエッジが下から上へ流れる |
| MN-101 | 環境設備の隣接 | 同上 | 散布機が行内で利用設備の隣に並ぶ |
| MN-102 | 台数分表示 | 同上で「設備を台数分表示」を有効化 | 散布機ユニットが担当環境の利用ユニットの最小層に置かれる |
| MN-103 | 同名レシピの識別 | 炭塊など同名レシピを持つ計画でペア候補を開く | 候補ラベルが「炭塊（芽針）」「炭塊（サンドリーフ）」のように説明付きで区別できる。供給内訳と流量調整ヒントも同じ表記になる |
| MN-104 | 採取素材の緑化 | 採取素材を含む計画をグラフ表示 | 採取ノードが出ず、採取供給のあるアイテムノードが緑色で、メタ行に「採取 X/分」が読める |
| MN-105 | 採取と生産の併存 | 採取上限を超えて生産も走る計画 | 併存アイテムも緑色になり、採取量が併記される |
| MN-106 | 採取なしの計画 | 採取素材を含まない計画 | 緑ノードは出ず、ノードはアイテムと設備のみ |
| MN-107 | Admin 側の同一動作 | 管理ツール計算プレビューで同等の計画 | 層規則・ラベル併記・緑化が公開 App と同じ動作になる |
| MN-108 | 横表示での整合 | 同上を横表示へ切替 | 散布機が利用設備と同じ列に置かれ、ガスエッジが左から右へ流れる |
