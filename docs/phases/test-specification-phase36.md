**対象フェーズ**: Phase 36（グラフ描画領域の自動縦幅拡張とグラフツールバー集約）
**前提ドキュメント**: [implementation-plan-phase36.md](implementation-plan-phase36.md)、[decision-records.md](../decision-records.md)（仕様決定 CM・CN。関連: AO・BK・BL）

> 本書は Phase 36 の検査項目を ID 付きで管理する。実施結果は PR 本文に表で記録する。
> ID 採番: 変更は JS モジュールとコンポーネントの相互運用に閉じ、Domain・Application の契約は変わらないため xUnit の新規 ID は設けない。手動確認は MN-148〜（main の現行最大は Phase 34 の MN-144。PR #93 が MN-145〜147 を使用する見込みのため、その次から採番する）。

## 1. 自動テスト（xUnit）

新規ケースなし。変更対象は `flow-graph.js`・`FlowGraph.razor`・`CalculatorPanel.razor` の表示系であり、Domain・Application の入出力契約は不変である。既存テスト全緑（`dotnet test`）を回帰として確認する。

## 2. 手動確認項目（ブラウザプレビュー）

WebGPU 対応 Chrome で公開アプリの計算ページを開き、複数ランを持つ計画（例: 複数目標で層が深くなる構成）でグラフを出して確認する。ビューポート高さはブラウザウィンドウのリサイズや DevTools のデバイスエミュレーションで変えられる。

| ID | 確認内容 | 手順 | 期待 |
|---|---|---|---|
| MN-148 | 自動拡張の基本動作 | 既定高（420px）に収まらない深い計画でグラフを出す | 領域が自動で伸び、ズーム 1.0 前後で全ノードが読めるサイズで表示される。フィットボタンを押しても表示がほぼ変わらない |
| MN-149 | 自動拡張の上限 | ビューポート高さを超える内容の計画（またはウィンドウを縮めた状態）でグラフを出す | 領域はビューポート高さで止まり、縮小フィットで全内容が表示される |
| MN-150 | 手動リサイズの優先 | ハンドルをドラッグして高さを変えたあと、目標を変えて再計算する | 高さは手動指定のまま維持され、自動では変わらない |
| MN-151 | 自動への復帰 | MN-150 のあとハンドルをダブルクリックする | 手動指定が解除され、内容に合わせた高さへ自動で戻る |
| MN-152 | 下限の維持 | 浅い計画（1〜2 層）でグラフを出す | 領域は 420px（モバイル幅では 300px）を下回らない |
| MN-153 | 最大化との往復 | グラフを最大化してから復帰する | 最大化中は画面いっぱい、復帰後は自動高さへ戻る |
| MN-154 | 台数分切替の移設と最大化中の切替 | グラフのツールバーで「設備を台数分表示」を切替、最大化中にも切替する | チェックがグラフのツールバーにあり、通常・最大化の双方で台数分・集約の表示が切り替わる。結果ツールバーからは消えている |
| MN-155 | 横表示での適用 | 横表示へ切替して深い計画を出す | 横表示でも世界矩形の高さに合わせて領域が自動で伸びる |
| MN-156 | 既存操作の回帰 | パン・ピンチ・ズームボタン・フィット・縦横切替・ノードクリックの行ジャンプ・Esc 復帰を試す | 従来どおり動作する。ハンドルの単クリック（移動なし）では自動モードが止まらない |

## 3. 受け入れ条件との対応

- MN-148・149・152・155 が仕様決定 CM の自動拡張規則を、MN-150・151 が手動モードと復帰を、MN-153 が最大化中の休止を、MN-154 が仕様決定 CN を、MN-156 が既存挙動の回帰をカバーする
- `dotnet build`・`dotnet test` 全緑と `tools/validate_master.py` 通過を併せて確認する
