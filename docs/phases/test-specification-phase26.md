# Phase 26 テスト仕様

**対象フェーズ**: Phase 26（散布機のカバー可能台数と台数計算の機械数比例化）
**前提ドキュメント**: [implementation-plan-phase26.md](implementation-plan-phase26.md)、[decision-records.md](../decision-records.md)（仕様決定 BP〜BR。改定元の I）
**関連ドキュメント**: [test-specification-phase4.md](test-specification-phase4.md)（散布機台数上書きの先行群）、[test-specification-phase10.md](test-specification-phase10.md)（マスタスキーマ検査の先行群）

> 本書は Phase 26 の検査項目を ID 付きで管理する。実施結果は PR 本文に表で記録する。
> 前提: `CalculationFixtures.Env()` 等の環境フィクスチャに `CoverableMachines`（既定 4）を追加する。機械数の設計値はフィクスチャの XML コメントへ記す。

## 1. モデル検査（xUnit）

### 既定台数の機械数比例化（BQ）: EnvironmentTests

| ID | 内容 |
|---|---|
| ENV-07 | 機械数がカバー可能台数を超えると複数台になる。i-hp 65/分（f-asm 4 秒ペア、機械数 65×4/60 ≈ 4.33）で散布機 2 台・ガス消費 720/分・f-asm 5 台。従来式では散布機 1 台に留まる点を確認する |
| ENV-08 | 複数ランの機械数は合算される。i-hp 60/分（機械数 4.0）と i-std 12/分（機械数 1.0）の合計 5.0 → 散布機 2 台・ガス消費 720/分。レシピ数ではなく機械数で決まることを確認する。上限の共有は ENV-15 で検査する |
| ENV-09 | 機械数がカバー可能台数ちょうどなら 1 台で済む。i-hp 60/分（4.0 機）単独で散布機 1 台・ガス消費 360/分 |

### カバー上限の反映（BR）: EnvironmentTests

| ID | 内容 |
|---|---|
| ENV-10 | 上書き 1 台（CoverableMachines=4）で機械数 4.33 の需要は 4.0 機で頭打ちになる。i-hp 65/分・上書き 1 → i-hp 生産 60/分・未充足 5/分・警告 `EnvironmentCoverageExceeded` |
| ENV-11 | 上書き 0 台は環境を要する生産を全量未充足にする。i-hp 30/分・上書き 0 → 未充足 30/分・警告あり。環境要件の行は残り `DispenserCount=0`・`RequiredDispenserCount=1` |
| ENV-12 | 上書きが必要台数ちょうどなら制限は発生しない。i-hp 65/分・上書き 2 → 全量生産・警告なし |
| ENV-13 | カバー不足でも代替ペアへ自動切替しない。r-hp の環境ペア選択時に散布機を 0 へ下げても、8 秒の非環境ペアへは切り替わらず未充足のみが出る（切替はユーザーのペア選択で行う） |
| ENV-14 | 削減された機械分は必要台数の見積もりに含まれる。i-hp 65/分・上書き 1 で `RequiredDispenserCount=2`（(4.0 + 0.33)/4 の切上げ） |
| ENV-15 | 複数ランは同じ上限を展開順で分け合う。i-hp 60/分（4.0 機）＋ i-std 12/分（1.0 機）で上書き 1 → 先に展開された i-hp が容量 4.0 を占有し i-std は全量未充足 12/分。警告 `EnvironmentCoverageExceeded` が出る |
| ENV-16 | 削減された未充足が別経路の供給で解消されると、必要台数と警告は残存分に追従する。環境ペアの未充足を後段の副産物レシピが賄うフィクスチャで、解消分だけ `RequiredDispenserCount` が下がり、全量解消なら警告も出ないことを確認する（比例配分・計画書 §3.3） |

### 既存テストの改訂

| ID | 内容 |
|---|---|
| ENV-01 | F10 に `CoverableMachines=4` を持たせても期待は不変（機械数 2.0 → 散布機 1 台・ガス 360/分）。契約不変の確認として維持する |
| ENV-02 | 改訂。i-hp 30/分（2.0 機）＋ i-std 12/分（1.0 機）は合計 3.0 機 → 散布機 1 台・ガス消費 360/分。旧契約の「レシピ数 2 → 2 台・720/分」から BQ へ更新する本命の差分とする |
| ENV-03 | 上書き 3 台（必要台数超の指定）の受理は維持。カバー上限の観点でも上限 12 機 ≥ 機械数 2.0 で全量生産・ガス消費 1080/分・警告なし |
| ENV-04〜06 | 非有効イベント・負数上書きの既定フォールバックは変更なし。フィクスチャの `CoverableMachines` 追加のみ |

### 上限値の Application 側（PVD）: PlanViewDefaultsTests

| ID | 内容 |
|---|---|
| PVD-06 | `DispenserLimit` は環境要件の `RequiredDispenserCount` を返す。カバー不足で稼働が止まった環境でも自動値が返る（distinct レシピ数を数えない） |

### 未調整ビューの上限反映（VWU）: UnadjustedViewTests

| ID | 内容 |
|---|---|
| VWU-07 | 未調整ビューでも環境ランはカバー上限を超えない。環境ペアのランと非環境のランが同じ設備を共用するフィクスチャで上書き 1・未調整表示 → 環境ランの供給は設備倍率の拡大ではなくカバー残量で頭打ち、非環境ランは設備倍率どおり拡大する |
| VWU-08 | 未調整ビューの残カバー量も計画の `RunOrder` 順で占有される。環境ラン 2 件で上書きが不足する計画の未調整表示で、先のランが拡大後のサイクルで残量を消費し、後のランは残量の範囲に留まる |
| VWU-09 | 未調整の拡大は後のランの調整済み生産を奪わない。先の環境ランが設備倍率で拡大できる計画で未調整表示しても、各環境ランは調整済みサイクルを下回らない（調整済み分の保留・計画書 §3.4） |

## 2. 手動確認項目

E2E 検証は WebGPU 対応 Chrome で行う。台数の自動値・未充足・警告は実マスタ（息壌の安定環境）で検証し、管理ツールの環境編集は `admin-driven-fixture-blazor-testing`・`fixture-injection-blazor-testing` の手順に従う。

| ID | 対象 | 条件 | 期待 |
|---|---|---|---|
| MN-109 | 台数の機械数比例 | 同梱マスタで息壌 31/分 | ガス散布機 自動 1 台・不活性ガス 6/分（現状と同じ） |
| MN-110 | 複数台の自動値 | 息壌 150/分（機械数 5.0） | 散布機 自動 2 台・不活性ガス 12/分・天有洪炉 5 台 |
| MN-111 | カバー不足の未充足 | 息壌 150/分 で散布機を 1 に下げる | 息壌生産が 120/分 に頭打ち、未充足 30/分 とカバー不足警告が出る。ペア選択は安定環境ペアのまま |
| MN-112 | 0 台指定 | 息壌 150/分 で散布機を 0 にする | 息壌が全量未充足になり、環境行は「自動 2 台まで」のまま残る。2 へ戻すと未充足が解消される |
| MN-113 | ヒント文 | 環境節 | ヒントがカバー上限の効果（下げると超過分が未充足になる）を説明している |
| MN-114 | Admin 側の同一動作 | 管理ツール計算プレビューで同等の計画 | 自動台数・カバー不足の未充足・警告が公開 App と同じ動作になる |
| MN-115 | 環境編集 | Admin の環境編集ページ | 「カバー可能台数」欄が編集でき、エクスポート JSON に出力される |
