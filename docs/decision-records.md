# 仕様決定記録（次期版）

次期 Web アプリ（[requirements.md](requirements.md)）のレビューと協議で確定した、仕様上の判断事項を記録する。
本記録は新規リポジトリでの作り直しに伴う新しい番号体系であり、旧リポジトリの決定は「旧 BA」のように参照する。
確定した決定は requirements.md 本文の該当箇所にも反映し、本文と本記録が矛盾しない状態を保つ。

| # | 項目 | 決定 |
|---|------|------|
| A | リポジトリ戦略 | 新規リポジトリ `Tkg-tamagohan/Endfield-AIC-Web` で作り直す。既存リポジトリ `Endfield-AIC-Planner` は参考実装として凍結し、README に凍結と後継への案内を追記する。GitHub Archive は新アプリ稼働後に判断する。本決定記録は新番号体系とし、旧リポジトリの仕様決定は「旧 BA」のように参照する |
| B | アーキテクチャ | Blazor WebAssembly（スタンドアロン、.NET 8）＋ Cloudflare Pages の静的配信のみで構成し、Workers・D1 は持たない。マスタ JSON はビルド成果物への静的同梱で配信する。共有データ（共有レイアウト・ユーザー紐付けデータ）が復活した時点でサーバー側要素の追加を再検討する |
| C | 移植範囲 | Core のモデル・計算・検証を C# のまま移植し、新モデルへ適合修正する（Core は外部依存ゼロの net8.0 で、WASM 上でそのまま実行できることを確認済み）。Infrastructure（EF Core・SQLite）・Layout・WPF（App/Admin）・旧 JSON との相互互換は移植しない。マスタ JSON スキーマは新系統で v1 に振り直す（旧データは実投入前の骨格のみで移行需要がないため） |
| D | マスタの原本と更新経路 | 原本は新リポジトリ内のマスタ JSON とし、PR レビュー＋CI/ローカル検証で管理する。Pages のデプロイで配信され、更新は JSON 差し替えコミットで行う。サーバー側の即時配信経路は持たない |
| E | 管理ツールの形と公開範囲 | 管理ツールは、ブラウザ内でマスタ JSON を読み込み・編集・検証・計算プレビュー・エクスポートする別 Blazor WASM アプリとする。別 Pages（専用ドメイン）にデプロイし、Cloudflare Access（Zero Trust 無料枠、メール OTP）で管理者以外を遮断する。公開アプリと同一 WASM 内のルート分離は、クライアント側ルーティングで回避できるため採らない。書き込み API は持たず、エクスポート物をリポジトリへコミットする運用とする |
| F | 既定のレシピ選択と将来の最適化 | 既定は `VersionAdded` 最新のレシピ × `CycleTime` 最小のペアとし、アイテム単位の代替選択（RecipeOverride 相当）でユーザーが切り替える。リリース後に「設備台数最小」「消費電力最小」「採取素材最小」「設備面積最小」の最適化バリエーションを実装する予定とし、その前提として設備は縦横の大きさを保持する。設備面積最小の計算はパイプ・ベルトコンベアの経路を考慮しない |
| G | 設備の属性 | 計算ドメインの設備は共通属性（N）に加え、`Width`・`Height`・`PowerConsumption` を持つ。縦横は「設備面積最小」最適化（F）のために保持する。合成設備の保持枠・入出力ポートは廃止（W）。発電設備の識別属性は発電モデル廃止（Y）に伴い持たない |
| H | 環境モデル | `Environment` エンティティを新設し、消費アイテム（ItemId＋個/分）・供給設備（FacilityId）を持つ（供給範囲は廃止、W）。環境条件は RecipeFacility ペアの属性（`EnvironmentId`、null=不要）とする。イベント限定環境は現状存在しないが、`GameEventId` を同型で持てるようにする |
| I | 環境の計算反映 | 散布機のカバー範囲は、レイアウト機能を持たないため計算・保持ともに行わない。散布機の台数はユーザーが環境ごとに整数で指定でき、既定はその環境を必要とする稼働中レシピ数（レシピにつき 1 台）。環境の消費アイテム（ガス等）×台数を需要へ追加し、散布機を設備要件・消費電力に計上する |
| J | 固定消費 | 設備が稼働するだけで消費される動力素材（アイテムの生産効率にかかわらず消費される継続消費）を、RecipeFacility ペアの要素（ItemId＋個/分、任意）として持つ。設備側の属性としないのは、レシピごとに値が変わりうる仕様変更への耐性のため。消費量は台数に比例させて計算へ組み込む |
| K | 対象デバイスと除外機能 | スマートフォン対応を要件に含め、レスポンシブ UI とする。工場レイアウト・キャンバス・共有レイアウト・自動配線・レイアウト由来のエンティティ（Layout/PlacedObject/CollisionClass）は新アプリに持ち込まず、将来も戻さない。PWA・ユーザーアカウント・サーバー保存・協調編集・収益化は対象外 |
| L | 進捗によるレシピ制限 | ゲームバージョン・進捗によるフィルタ UI は持たず、最高効率レシピが使えない場合はユーザーによる代替選択で対応する |
| M | 期間指定の計算 | 毎秒・毎分のレート表示に加え、日・時・分で指定した期間の個数換算を出力する。設備の消費電力合計は時間換算しない |
| N | 共通属性 | 全マスタエンティティ（Item・Environment・Recipe・Facility・GameEvent・GameMap）に `Id`・`Name`・`Description`・`IconKey`・`VersionAdded`（＋`VersionRemoved`、任意）を持たせる |
| O | 流量調整の表示 | 計算結果は「未調整（切上台数の最大稼働）」と「調整済（推奨流量制限で余剰抑制）」の 2 状態を切り替えられるようにする。目標レートがレシピ出力の整数倍でない場合は既定を調整済とする |
| P | RecipeFacility のキー | ペアの一意性は全要素の組（RecipeId・FacilityId・CycleTime・EnvironmentId・固定消費）で判定する |
| Q | 発電 | v1 では発電モデルを実装しない（現行スコープに発電・工場系要素がないため）。消費電力合計のみを出力する。発電モデル自体は廃止（Y）とし、旧実装（仮想アイテム・定格発電・燃料ループ）は参考情報として残すに留める |
| R | 継承する既存決定 | 次の既存決定を継承する: 副産物の他素材要求への充当と余剰表示（旧 K）、循環依存の検出と警告、輸送容量警告（ベルト 30 個/分・パイプ 60 個/分、旧 L 一部。単位は AM で改訂）、需要アイテムへの既定選択規則とペア選択規則（旧 I/BC）、計画内のレシピ→設備一意と衝突時の先勝ち＋警告（旧 BN）、1 アイテムの需要を複数設備へ分割しない（旧 BE）、ペア基準の整合性ガード（旧 Z・旧 BP 相当の意味検証）、アイコン規約（IconKey・マニフェスト・権利クリア画像のみ、旧 AM/AO/AP）、`DataVersion`/`SchemaVersion` による版管理と全置換更新（旧 Q/P）、有効イベントのコンテキスト指定（旧 AG 相当）、複数目標（旧 D）、採取素材の個/分表示（旧 C、AB で改称） |
| S | Origin | 廃止する。旧 `Origin`（Seed/User/Import）は Admin 作業 DB の行識別が用途であり、マスタ JSON 単独管理の新モデルでは区別を持たない |
| T | イベント体系 | `GameEventId` を Item・Environment・Recipe・GameMap に一様に持たせる（null=常設）。`GameEvent` は `Id`・`Name`・`ActiveFrom`・`ActiveTo`（null=期間なし・常設）。非有効イベントのイベント限定アイテムは生産・外部調達とも不可とし、需要が残れば未充足＋警告とする |
| U | 属性の異なるペア行の既定選択 | 同一 (RecipeId, FacilityId) で属性の異なるペア行が複数ある場合、既定は `CycleTime` 最小とし、同率は `EnvironmentId=null` を優先、さらに `FixedConsumption` なし/小を優先する。代替選択 UI はペア行単位で提示し、環境の有無が分かるよう併記する |
| V | 固定消費の台数基準 | 固定消費の需要計上は切上台数（実設置台数）×個/分 とし、調整済モードでも同じ基準とする。稼働中に継続消費するモデルのため、必要台数の実数値ではなく実設置台数が一貫する。ゲーム仕様で稼働率比例の消費が確認された場合は実数基準への変更を再検討する |
| W | 工場系属性の廃止 | 計算ドメインで使用しないため、Facility の `InternalSlots`・`InputPorts`・`OutputPorts` と Environment の `CoverageRadius` を削除する（G・H の保持方針を変更。`Width`・`Height` は F の最適化で使用するため保持）。将来工場系要素を作成する場合は、計算ドメインとは別の工場ドメインを用意して再定義する |
| X | イベント終了後の限定アイテム | 非有効イベントのイベント限定アイテムは生産・外部調達とも不可とし、需要が残れば未充足＋警告とすることを確定する（T の暫定扱いを正式採用）。ゲーム仕様で異なる挙動が確認された場合に再検討する |
| Y | 発電モデルの扱い | 廃止する。計算ドメインで使用しないため（Q の「将来の追加対象として温存」を変更）。将来再導入する場合は工場ドメインを別途用意して再定義する。消費電力合計のみを出力する方針は変わらない |
| Z | イベント期間の時刻解釈 | `GameEvent` の `ActiveFrom`・`ActiveTo` は時刻の瞬間（RFC 3339 の `Z`・オフセット付き表記）として解釈する。既定の有効判定は両端を閲覧者のローカル時刻へ換算した暦日で行い、`Z` とオフセット付きの書き方の違いで解釈が分かれないよう揃える。日付の読み取りは既定判定のたびに行い、ページを開き続けた場合も既定の鮮度を保つ（ユーザーが操作したチェックは既定の再評価から除外する） |
| AA | アイコンの正規化とアニメーション | アイコン画像の出力は一辺 128 ピクセル以下の正方形とする。クロップ領域が 128 ピクセルを超える画像は 128×128 へ縮小し、以下の画像は拡大もパディングもせず原寸の正方形で保存する（表示側は `object-fit: contain` で枠にフィットさせる）。アニメーション画像（GIF・APNG 入力）は全フレームへ同一規則を適用し APNG で保存する。APNG は PNG の拡張形式のため、`icons/<Key>.png` のファイル規約・`image/png` の MIME・マニフェスト構造は変更しない。デコードは WebCodecs の `ImageDecoder` を主経路とし、APNG 入力は同梱する UPNG.js のデコード機能を副経路とする。いずれの経路も使えない場合に限り、先頭フレームの静止画へ縮退する |
| AB | 用語「基礎素材」→「採取素材」 | 「基礎素材」を「採取素材」と改称する。`Item.IsBaseMaterial` は `IsGatherable`、`SupplyKind.RawMaterial` は `Gathered` とし、JSON フィールド・`Category` 値・UI ラベル・文書の用語も追従する。旧決定 F・R の「基礎素材」は同じものを指す |
| AC | マップと採取レート | `GameMap` エンティティを新設し、マップごとに採取素材の採取レート行を持つ。各行は「毎分の上限値」または「無限」のいずれかを指定する。選択したマップに採取レート行のない採取素材は、そのマップでは採取不可（上限 0）とする。マップ未選択時は全採取素材を上限なしとする。採取レート行は採取素材のみを指し、同一マップ内での ItemId 重複は認めない |
| AD | 採取上限の計算 | 計算ごとに 1 マップを選択する。需要は有効採取レートまでを採取とし、超過分は当該アイテムを産出するレシピで展開する（採取優先。従来のレシピ優先を変更）。代替レシピがなければ未充足＋警告とする。採取上限は需要の発生源を問わず適用する。非有効イベント所属のマップは選択候補から外し、選択状態が残った場合は全採取素材を採取不可（上限 0）として警告し、採取レートのユーザー上書きも無効とする（X と同型） |
| AE | 採取レートのユーザー上書き | 計算ごとに、採取素材の利用可能レート（個/分）をユーザーが指定できる。指定は有効レートの置き換えとし、空欄はマップ既定値（マップ未選択時は無制限）とする。マップ値を超える入力も許可する。上書きは有効なマップ選択に対してのみ適用され、非有効イベントのマップが選択状態で残った場合は無効とする。UI は散布機台数の指定と同型とする |
| AF | 消費・取得レートの単位統一 | ユーザー入力とモデル保持のレート単位を個/分に統一する。採取レートは個/分で新設し、`Environment.ConsumeRatePerSecond` → `ConsumeRatePerMinute`、`FixedConsumption.RatePerSecond` → `RatePerMinute` と改名して個/分化する。`SchemaVersion` は 1 のままとする（実データ投入前で移行需要がない） |
| AG | Admin 計算プレビューの追従 | 管理ツールの計算プレビューを公開版と同等の機能へ揃える（ペア代替選択・散布機台数入力・単位切替と期間入力・マップ選択・採取レート入力）。razor ページの共有化（RCL 化）は見送り、残課題として remaining-issues.md に記録する |
| AH | 散布機台数の保持値と自動上限の整合 | ペア変更などで環境の自動上限が下がり、再計算をまたいで保持した散布機台数の入力が新しい上限を超えた場合、その入力は自動値（空欄）へ戻す。上限へのクランプは行わない（上限値=自動値のため計算結果は同じで、明示値が残るより自動復帰のほうが表示として正直）。表示中の計画は戻す前の台数で計算済みになるため、戻した場合は直ちに整合後の入力で再計算し、表示と入力を一致させる。無効になった保持値を破棄する採取レート上書きの既存規則（AD・AE）と同型。公開版と管理ツールで共通の処理とする |
| AI | 生産フローグラフ | 計算結果の供給関係（採取→設備→アイテム）を有向グラフとして結果画面に表示する。エッジと流量比例の粒子は WebGPU で描画し、ノードは DOM カードで構成するハイブリッドとする。従来のリスト表示は維持して併用する。実施は公開アプリのみとし、管理ツールへの展開は別 Phase。立体の工場プレビューは引き続き対象外（K） |
| AJ | グラフの実装方式 | 外部依存を持たない ES module の vanilla JS＋WGSL（`wwwroot/js/flow-graph.js`）とし、Blazor とは `IJSRuntime` の動的 import で連携する。ノードのラベル・アイコン・クリック処理は DOM 側に任せ、canvas はエッジと粒子だけを描く |
| AK | グラフの既定表示とフォールバック | WebGPU が使える環境ではデスクトップ幅でグラフを既定展開し、ユーザーが表示・非表示を切り替えられる。非対応ブラウザやアダプタ取得失敗時はグラフ領域と切替ボタン自体を出さず、リスト表示のみとする。スマートフォン幅では既定を折りたたみとする |
| AL | グラフ内アイコンの扱い | ノードは DOM で描き、アイコンはリスト表示と同じく `<img>` で表示する（APNG は従来どおり再生される）。アイコンは原寸（一辺 128 ピクセル以下）を超えて拡大表示しないよう、ノード内は小さなサムネイルとし、ズーム上限でも原寸以下に抑える |
| AM | 輸送容量と推奨流量制限の単位 | ベルトの輸送容量は 30 個/分、パイプは 60 個/分とする。`FlowAdjustment` の要求流量・推奨制限も個/分で出力する。AF（Phase 9）で個/s 据え置きとしたこれらの値は単位誤認だったため改訂する。表示単位切替の「毎秒」選択肢（要求量・供給量の表示単位）は変更しない（M） |
| AN | 輸送容量超過の判定基準 | 容量超過の判定は、設備 1 ユニットへの入力流量がそのアイテムの輸送容量を超える場合に限定する（台数・レーンを増やして解消できる集計超過は対象外）。判定対象は設備への入力（レシピ入力・固定消費・環境消費）で、生産出力・採取供給・目標需要だけの超過は対象外とする。グラフの赤化は超過したエッジと両端ノードに適用し、集約表示では構成するユニットエッジのいずれかが超過していれば集約エッジも赤化する（台数分表示で正常なら集約表示でも正常）。計算本体の警告（TransportCapacityExceeded）も同じ基準へ改める |
| AO | グラフの設備台数分表示 | 生産フローグラフに、設備ノードを実設置台数（切上台数）ぶん個別に描く切替を追加する。ユニットノードは設備の入出力流量を占有台数の比率で分割して持ち、ランの占有は機械数をユニット容量 1.0 へ逐次充填する。散布機は環境ごとの散布機台数ぶんの専用ユニットとする。容量超過判定（AN）はユニットへの入力エッジ単位で行う。切替の既定は従来の集約表示とする |
| AP | グラフ粒子密度の飽和 | 生産フローグラフの粒子個数は、エッジ流量のグラフ内最大値に対する比率ではなく絶対流量に比例させ、30 個/分で飽和とする（30 個/分以上のエッジは同一密度）。流量差の見分けは粒子の速度（従来どおり最大流量比）が担う。高流量の計画で密度が過剰になり視認性が低下したため、Phase 15 の相対比仕様から改訂する |
| AQ | 正味増循環の定常解 | 需要展開で検出した循環のうち、検出パス上の各レシピ比率（隣接アイテムの入力量÷出力量）の積であるループゲインが 1 未満のものを正味増とみなし、打ち切った残差を解放して展開・引き戻しの固定点反復を続け、外部投入なしの定常解を求める。種↔作物に限らず選択済みレシピが作る任意の循環に適用し、採取素材が絡む場合も採取充当を先に行う従来規則に従う。解けた循環は警告を出さない。ループゲイン 1 以上・反復上限到達・残差が縮まない循環は従来どおり未充足＋CycleDetected 警告とする（旧 K の循環検出を拡張） |
